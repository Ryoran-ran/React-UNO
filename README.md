# IROHA — 色をつなぐ、流れを変える。

React + TypeScript製の、2〜8人で遊べるオリジナルのカラーカードゲームです。添付の「UNO風カードゲーム 開発仕様書 v1.0」に基づき、Phase 1〜5を実装しています。既存製品の画像・ロゴ・外部フォントは使用していません。

## 起動

この作業環境では **[起動.cmd](./起動.cmd) をダブルクリック**し、表示された `http://127.0.0.1:5173/` をブラウザーで開いてください。5173番が使用中の場合は画面に表示されたURLを使います。現在の環境には通常のNode.jsコマンドがなかったため、検証用の公式Node.js LTSを `.tools/node.exe` に配置しています。システムの設定は変更していません。

通常の開発環境ではNode.js 22.12以上（24 LTS推奨）を用意します。

```sh
npm install
npm run dev
```

このワークスペースの依存パッケージはBunで取得済みです。`bun.lock` にバージョンを固定しています。Bunを使う場合は `bun install --frozen-lockfile` でも復元できます。ここで用意したNode.jsから直接実行する場合は次のとおりです。

```powershell
.\.tools\node.exe scripts/run.mjs dev
.\.tools\node.exe scripts/run.mjs test
.\.tools\node.exe scripts/run.mjs build
.\.tools\node.exe scripts/run.mjs preview
```

## 遊び方と機能

- 「テーブルにつく」で対戦開始。最初のプレイヤーはランダムです。
- カードは全108枚、固有ID付き。各プレイヤーに7枚配り、最初の場札は数字です。
- 色・数字・記号の一致、またはワイルドで出札。明るい手札だけをクリックできます。
- 手動でワイルド（即時指定の+4を含む）を選ぶと、出す前に色を選びます。選択中はカードを手札に残し、キャンセル・×・Esc・背景クリックで取り消せます。色の選択と出札は1回のアクションで確定し、カードの移動演出が始まります。攻撃後指定の+4や、自動ドローですでに出されたワイルドの色指定は確定済みの処理なので取り消しません。
- 人間1〜8人とCPU0〜7人を自由に組み合わせ、名前を設定できます。
- CPUはEasy／Normal／Hard。速度も変更できます。CPUの判断処理は、公開ルールで許可された情報だけを受け取ります。
- 通常対戦と順位戦。2人対戦、および順位戦の残り2人では、通常のスキップ／リバースで自分の番に戻ります。
- 攻撃は重ねがけ／同種で無効化／ドローカードでの回避不可の3方式。+2／+4混合、リバース反射、スキップ転送、各連続使用を個別に設定できます。
- 反射／転送は攻撃色との一致が必要。反射で進行方向も変わります。同種ドローによる防御では色を問いません。
- +4の色指定は即時／攻撃の解決後の2方式。事後指定は最後に+4を出した人が担当します。
- 通常ドローは1枚引いてパス／出せるまで引いて自動出札。任意ドローも変更できます。
- 手札は自分だけ／全公開／CPUも公開。人間が複数の非全公開モードでは、交代画面で手札を隠します。
- 残り1枚の「UNO!」は本人の手札の上に約1.5秒表示します。自分は手札エリアの上、CPUはその席の手札付近に表示し、中央の場札をふさぎません。ゲーム判定は止まりません。
- カードを出すと手札の位置から中央へ移動して着地し、傾きを変えて場札に重なります。CPUの非公開カードは移動中に表へ返ります。フェルト調のテーブルと木の縁、手札の傾きも加えています。「動きを少なくする」またはOSの軽減設定では移動演出を省略します。
- スキップとリバースはカードの着地後に約0.9秒の効果演出を表示します。スキップは対象の席に「お休み」、リバースは回転する矢印と新しい方向を表示します。攻撃中はそれぞれ「転送」「反射」に切り替え、枚数と実際の受け手を示します。残り2人のリバースは「もう一度」の表示になります。文字・矢印・席の強調は画面上の重ね描きなので、カードやテーブルの配置を変えません。
- 通常ドローとドロー攻撃の受け取りでは、山札から各プレイヤーの手札へ順番にカードが移動します。非公開の相手のカードは裏向きのままです。多枚数では最大8枚の代表アニメーションと実際の枚数を表示します。演出が終わるまで既存の手札位置を固定し、新しいカードは右端へ追加します。山札・場札・手番表示・攻撃表示は高さを確保した固定枠に置き、表示内容や枚数で中央のカードが移動しないようにしています。
- **攻撃を引いた後の続行ルール**: 「設定 → ドロー → 攻撃で引いた後も自分の番を続ける」をONにすると、+2・+4の攻撃を受けて引いた人が、そのまま通常ターンを行えます。初期値はOFF（従来どおりターン終了）。通常の1枚ドローには影響せず、事後の色指定や上がり確定が必要な場合は、それらを終えてから続行します。設定は次の対戦から適用されます。
- メニューと対戦画面は画面の高さに合わせて配置します。手札は横スクロールせず重ねて並べ、「手札一覧」で広げて選べます。参加者・ルール・記録は上部から開き、確認中はCPUを一時停止します。設定は4カテゴリに分け、プレイヤー名は4人ずつ切り替えます。詳細一覧などの長い内容だけをダイアログ内でスクロールし、保存や通常の対戦操作は画面内に残します。
- 席順は、自分の手札を下側の席として「左側を上へ → 上辺を左から右へ → 右側を下へ」の時計回りです。2〜8人、画面サイズ、人間の交代に対応し、リバース時は同じ席を逆順に進みます。順位が確定した人の席を詰め直さず、以降の手番だけを飛ばします。
- 手番は中央の大きな表示、本人の席の明るい枠と「手番」バッジで確認できます。自分の番は手札の背景も金色になります。反撃・色選択・CPUの思考・詳細確認による一時停止をそれぞれ区別し、読み上げにも現在の手番を伝えます。
- 山札切れでは最上部の場札を残して再シャッフル。引けるカードが尽きた分は免除します。
- 対戦とルールの設定はlocalStorageに保存します。対戦途中の再開は初期仕様に含めていません。

## オフライン

ゲーム本体は外部APIやサーバーとの通信を必要としません。開発サーバーも端末内だけで動作します。

`npm run build` のあと `npm run preview` で本番版を開くと、Service WorkerがHTML・JavaScript・CSS・アイコンをキャッシュします。一度読み込みとキャッシュが完了すれば、同じURLでネットワークが切れていても起動できます。初回のパッケージ取得や別端末への配信には接続が必要です。Service WorkerはlocalhostまたはHTTPSが必要で、`dist/index.html` の直接ダブルクリックは対応していません。

## 構成と拡張

```text
src/
  types/        カード・プレイヤー・設定・状態・アクションの型
  engine/       ゲーム生成、純粋なreducer、出札、攻撃、順位、ターン、山札
  rules/        基本ルールとカード効果のレジストリ
  cpu/          公開情報の抽出と3段階の判断処理
  stores/       Zustand。設定保存とエンジンへのアクション送信
  components/   カード、手札、プレイヤー、テーブル、色選択、設定、結果
  utils/        シード付きシャッフル、設定読み込み・保存
```

ゲーム状態はシリアライズ可能です。`gameReducer(state, action)` は入力状態を変更せず、不正操作は元の状態を返します。乱数シードを状態に保持し、配札から山札補充まで同じ入力を再現できます。ReactやZustandにゲーム判定を置いていません。

新しいカードは `rules/ruleRegistry.ts` の `registerCardRule` で登録できます。使用判定と `draw`／`reverse`／`skip`／`chooseColor` の宣言的効果を定義し、`createDeck(extraCards)` に固有IDを持つカードを追加します。標準と異なる攻撃防御の種類を追加する場合は、独立した `attackManager.ts` を拡張します。上がり確定方針は `rankingManager.ts` に分離しています。
